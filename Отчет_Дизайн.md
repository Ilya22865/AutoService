**Проект:** PitStop — Автосервис (г. Витебск)  
**Стек:** React 19 + TypeScript + Vite 8 (Frontend)  
**Дата:** Май 2026

## 1.1. Основы UI/UX-дизайна

### Анализ существующих интерфейсов

**Успешные решения в проекте:**
- **Hero-секция** (Hero.tsx) — чёткий призыв к действию («Записаться на ремонт») + статистика (15+ лет, 5000+ авто, 98% клиентов). Это снижает тревожность пользователя и формирует доверие.
- **Навигация** — фиксированное меню с якорными ссылками на разделы: Главная → Услуги → Запчасти → О нас → Отзывы → Контакты. Пользователь всегда понимает, где находится.
- **Форма записи (OrderForm.tsx)** — минимальное количество полей (имя, телефон, марка, услуга, комментарий), что снижает барьер входа.
- **Карточки услуг (Services.tsx)** — каждая услуга представлена иконкой, заголовком и описанием. Пользователь может быстро сканировать и выбирать.

**Неудачные решения:**
- **Отсутствие валидации в реальном времени** — форма заказа не подсвечивает ошибки до отправки, пользователь узнаёт о проблеме постфактум.
- **Однотипные заказ (OrderPage) и форма записи (OrderForm)** — дублирование функционала на Home и отдельной странице вводит в заблуждение.
- **Нет прогресс-бара** при оформлении заказа из нескольких шагов.

### Целевая аудитория

| Сегмент | Потребности | Особенности |
|---|---|---|
| **Владельцы авто (25–55 лет)** | Быстрая диагностика, ремонт, запись онлайн | Ценят скорость, хотят видеть цены заранее |
| **Постоянные клиенты** | История заказов, статус ремонта, напоминания о ТО | Нужен личный кабинет |
| **Сотрудники СТО** | Управление заказами, клиентская база, отчёты | Нужна панель с фильтрами и быстрым доступом |
| **Клиенты с низкой цифровой грамотностью** | Простой интерфейс без лишних шагов | Крупные кнопки, понятные подписи |

### Принципы юзабилити (по Нильсену)

| Принцип | Реализация в проекте |
|---|---|
| **Видимость состояния системы** | Статусы заказов с цветовой индикацией (emp-badge--green/yellow/blue/red) |
| **Соответствие реальному миру** | Названия услуг на русском, привычные термины («Ходовая часть», «ГРМ») |
| **Контроль и свобода** | Кнопки «Назад к заказам», «На главную» |
| **Распознавание вместо вспоминания** | Все услуги и запчасти отображаются списком, не нужно помнить артикулы |
| **Эстетика и минимализм** | Чистый дизайн, достаточно воздуха между секциями |
| **Помощь в распознавании ошибок** | Цветные бейджи статусов, сообщения об ошибках в формах |

## 1.2. Проектирование пользовательских потоков

### User Flow: Регистрация (Register.tsx)

```
[Главная] → [Регистрация]
  ├── Выбор роли (Клиент / Сотрудник)
  │   ├── Клиент: ФИО, Телефон, Email, Адрес, Пароль
  │   └── Сотрудник: ФИО, Email, Должность, Зарплата, Пароль, Код доступа
  ├── Валидация: Email (Hunter.io), пароль ≥ 8 символов, совпадение паролей
  ├── [Успех] → JWT → Redirect (кабинет клиента / панель сотрудника)
  └── [Ошибка] → Показать сообщение об ошибке
```

**Проблемы:**
- Нет подтверждения email (верификация через Hunter.io только проверяет существование)
- Нет восстановления пароля (заглушка «Забыли пароль?» не работает)
- Нет индикации сложности пароля

### User Flow: Авторизация (Login.tsx)

```
[Главная] → [Вход]
  ├── Email + Пароль
  ├── [Успех] → JWT → Redirect (Employee → /employee, Client → /account)
  └── [Ошибка] → «Неверный логин или пароль!»
```

**Проблемы:**
- Нет remember-me (чекбокс есть, но логика не реализована)
- Нет ограничения попыток входа (brute-force)

### User Flow: Оформление заказа (OrderPage.tsx + OrderController.cs)

```
[Главная / Услуги] → [Оформить заказ]
  ├── Шаг 1: Данные клиента (имя, телефон, email, адрес)
  ├── Шаг 2: Данные авто (марка, год, VIN, госномер)
  ├── Шаг 3: Выбор услуг (с поиском)
  ├── Шаг 4: Выбор запчастей (с поиском)
  ├── Шаг 5: Комментарий
  ├── Итого (динамический подсчёт)
  └── [Отправить] → POST /api/order/addOrder → Статус Pending
```

**Проблема:** Frontend НЕ отправляет данные в API (заглушка `alert`). Поток обрывается на клиенте.

### User Flow: Панель сотрудника

```
[/employee] — Dashboard (статистика, последние заказы)
  ├── Заказы (/employee/orders) — таблица с фильтрацией по статусу
  │   └── Детали заказа (/employee/orders/:id) — просмотр/изменение статуса
  ├── Клиенты (/employee/clients) — таблица клиентов с поиском
  └── [Выход] → Очистка токена → Redirect на главную
```

## 1.4. Адаптивный и инклюзивный дизайн

### Адаптация под устройства

Проект использует кастомные CSS-медиазапросы (все стили в `App.css` и `index.css`):

| Устройство | Поведение |
|---|---|
| **Desktop (≥1024px)** | Полная версия: горизонтальная навигация, сетка 3 колонки |
| **Tablet (768–1023px)** | Сетка 2 колонки, уменьшенные отступы |
| **Mobile (<768px)** | Сетка 1 колонка, бургер-меню, вертикальный layout форм |

**Ключевые адаптивные решения:**
- **Бургер-меню** в Header.tsx (три линии, сворачивает навигацию)
- **Формы** перестраиваются в один столбец (класс `auth-card__row`)
- **Таблицы** в панели сотрудника: на мобильных предполагается скролл или сворачивание (требует доработки)
- **Гарантированная ширина**: `.container { max-width: 1200px; margin: 0 auto; }` с паддингами

### Требования доступности (WCAG)

| Критерий | Статус | Комментарий |
|---|---|---|
| **Контрастность (1.4.3)** | ✅ Выдержан | Красный `#d4332a` на белом — 5.2:1 (AA) |
| **Масштабирование текста (1.4.4)** | ⚠️ Частично | Используются `rem` и `px`, проверено до 200% |
| **Навигация с клавиатуры (2.1.1)** | ⚠️ Частично | Формы доступны, но нет skip-link |
| **Alt-тексты для изображений (1.1.1)** | ❓ Не везде | Логотип в Header без `alt` |
| **ARIA-атрибуты (4.1.2)** | ⚠️ Минимально | `aria-label` только на бургер-кнопке |
| **Фокус (2.4.7)** | ⚠️ Не настроен | Отсутствуют видимые `:focus-visible` стили |

**Что добавлено:**
- `aria-label="Меню"` на бургер-кнопке
- `required` на обязательных полях форм

**Что требуется доработать:**
- Добавить skip-link для пропуска навигации
- Настроить `:focus-visible` для всех интерактивных элементов
- Добавить `alt` к изображению логотипа

## 1.5. Микроанимации и интерактивность

### Существующие анимации

| Элемент | Тип | Реализация |
|---|---|---|
| **Бургер-меню** | CSS-трансформация | Три линии превращаются в крестик через класс `.open` |
| **Кнопки** | `:hover` | Затемнение/осветление фона (через CSS) |
| **Карточки услуг** | `:hover` | Подъём (box-shadow, transform) |
| **Переходы между страницами** | Отсутствуют | Мгновенная смена через React Router |

### Рекомендованные сценарии микроанимаций

```
1. Кнопка "Отправить заявку":
   [Отправить] → спиннер на 1-2 сек → галочка "✓ Отправлено"
   (улучшает восприятие скорости)

2. Карточки каталога при наведении:
   Масштаб 1→1.02, тень увеличивается
   (создаёт ощущение "поднятия")

3. Статус заказа при обновлении:
   Бейдж плавно меняет цвет через transition
   (визуальная обратная связь)

4. Модальное окно/уведомление:
   Появление с opacity 0→1 + translateY(-10→0)
   (естественное появление)

5. Шаги оформления заказа:
   Прогресс-бар с плавным заполнением
   (пользователь видит, сколько осталось)
```

### Оценка влияния

| Анимация | UX-эффект | Производительность |
|---|---|---|
| Hover на карточках | + Понятно, что элемент кликабелен | GPU-композиция (transform) |
| Спиннер на кнопке | + Снижает тревожность ожидания | CSS-анимация |
| Прогресс-бар | + Прозрачность процесса | CSS transition |
| Переходы страниц | + Плавность, премиальность | React Router + CSS |

Анимации реализуются через CSS `transition` (свойства `opacity`, `transform`), чтобы не нагружать CPU JavaScript-анимациями.

## 1.6. Тестирование и итерации

### План юзабилити-тестирования

**Сценарии для тестирования:**

| Сценарий | Действия пользователя | Ожидаемый результат |
|---|---|---|
| **Регистрация клиента** | Открыть сайт → Нажать «Регистрация» → Заполнить форму → Отправить | Переход в личный кабинет |
| **Оформление заказа** | Выбрать услуги → Добавить запчасти → Ввести данные авто → Отправить | Заказ создан (Pending) |
| **Просмотр статуса** | Войти → Личный кабинет → Список заказов | Виден статус каждого заказа |
| **Панель сотрудника** | Войти (Employee) → Дашборд → Фильтр заказов → Смена статуса | Статус обновлён |

### Выявленные проблемы (по результатам анализа кода)

| № | Проблема | Серьёзность | Решение |
|---|---|---|---|
| 1 | OrderPage не отправляет данные в API | Критическая | Реализовать вызов `POST /api/order/addOrder` |
| 2 | Нет валидации VIN-номера | Средняя | Добавить regex-валидацию (17 символов) |
| 3 | «Забыли пароль?» не работает | Средняя | Реализовать восстановление пароля |
| 4 | Чекбокс «Запомнить меня» не функционален | Низкая | Реализовать remember-me (localStorage vs sessionStorage) |
| 5 | LCP (самая большая отрисовка контента) | Средняя | Оптимизировать изображение Hero |
| 6 | Нет индикации загрузки на страницах | Средняя | Добавить skeleton/spinner при запросах |
| 7 | Нет сообщения при пустом результате поиска | Низкая | Показывать «Ничего не найдено» |
| 8 | Отзывы не сохраняются (форма-заглушка) | Средняя | Реализовать API для отзывов |
| 9 | Нет 404-редиректа для неавторизованных | Низкая | Добавить проверку токена в роутах |
| 10 | Нет подтверждения действия (удаление и т.д.) | Низкая | Добавить confirm-диалоги |

### Метрики для оценки

| Метрика | Текущее значение | Цель |
|---|---|---|
| **Время до первого заказа** (новый пользователь) | ~3 мин (регистрация + заказ) | < 2 мин |
| **Количество шагов до заказа** | 5 шагов (форма) | 3 шага |
| **Конверсия регистрация → заказ** | Не измерено | > 60% |
| **Time on Task** (оформление заказа) | Не измерено | < 90 сек |
| **Ошибки пользователя** (на 1 сессию) | Не измерено | < 2 |

### Доработанный дизайн (рекомендации)

1. **Уменьшить количество шагов** — объединить «данные клиента» и «данные авто» в один блок
2. **Добавить прогресс-бар** для многошаговых форм
3. **Реализовать живой поиск** по услугам и запчастям с debounce
4. **Добавить моментальную валидацию полей** (onBlur)
5. **Сделать главную страницу короче** — вынести Каталог на отдельную страницу
6. **Добавить уведомления (toast)** об успешных/неудачных действиях
7. **Реализовать тёмную тему** (CSS-переменные + toggle)

## Заключение

Дизайн веб-приложения «PitStop» выполнен в едином стиле с использованием продуманной цветовой палитры, типографики и набора компонентов. Основные пользовательские потоки (регистрация, авторизация, заказ, панель сотрудника) спроектированы и частично реализованы. Главные недостатки на данный момент — отсутствие связи фронтенда с API по ряду сценариев (заказ, отзывы) и неполная реализация адаптивности/доступности. Рекомендуется провести юзабилити-тестирование с реальными пользователями и итеративно улучшить дизайн на основе полученных данных.
